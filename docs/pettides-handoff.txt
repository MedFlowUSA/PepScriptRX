Customer experience
Distinct navy/teal, responsive brand shell with supplied logo and hero;
four concept cards and individual detail pages; About; interest list;

when published resources exist. No human portal, calculator, treatment,
cart, checkout, or AI treatment assistant is included in PetTides navigation.

remain unreviewed. Unknown or draft article URLs reveal no draft content.

Review workflow
Main admin can edit articles and source URLs, submit for review, record
approval, publish and unpublish. The database requires In Review before
approval and Approved before publication, source verification, at least one
source, and a recorded authenticated reviewer/time. Substantive edits reset
approval and unpublish the article. Review records are created on an actual
approval transition only. Assign appropriately qualified reviewers before
using these controls; platform admin access does not imply veterinary expertise.

Ownership, commissions and purchase restrictions
PepScriptRX owns PetTides directly. No rep, parent, outside owner, payout
recipient, or commission is seeded. Existing commission configuration is
untouched. Concepts use a separate preview content table rather than the
saleable product catalog, so there are no payable catalog IDs to select.
Database triggers reject PetTides order identity in store/source/product/
cart metadata on shared patient submission insert/update, including service
role writes, and reject related fulfillment. Discounts cannot bypass this.
There is no launch/activation button; completing checklists does not unlock sales.

Interest and discounts
The contact form collects optional name, email and explicit updates consent
only. A validated RPC reuses portal_age_lead_captures with portal_id=pettides;
it does not claim age confirmation or create medical/order submissions.
PetTides admin shows the latest 500 contacts; existing main Leads infrastructure
retains the underlying records. No emails or external messages are sent.
An admin action can prepare an inactive planning record in the existing
aactivated_promo_links table, scoped PETTIDES. No record/code is created by
the migration. Admins can edit fixed amount, title, code and product scope;
a trigger forces PetTides discount records inactive and rejects non-platform
writes. The inspected promo-link schema lacks percentage types, scheduled
dates and usage limits; adding those requires a shared-system enhancement
before launch. No duplicate payment or discount engine was created.
No orders or margin results exist; costs default unknown. Processing fees,
shipping, manufacturing and distribution costs are not established/tracked
for these preview concepts. No financial estimates have been fabricated.

Configuration required
Review and apply ONLY supabase/migrations/20261027120000_pettides_preview.sql
to an appropriate local/staging database before expecting persistence.
Do not blindly push this repository's other pending migrations; the checkout
contains substantial pre-existing uncommitted changes and migration history.
The migration adds two RLS-protected preview content tables, narrowly scoped
RPCs, review enforcement, shared-order/fulfillment guards and discount guards.
It depends on existing is_platform_admin(), portal_age_lead_captures,
patient_submissions, fulfillment_orders, and aactivated_promo_links.
Existing VITE_SUPABASE_URL and VITE_SUPABASE_ANON_KEY are needed for data.
With no connection/migration, public preview uses safe static concepts and
no published articles; interest submission reports failure rather than
pretending it saved, and admin reports missing configuration.
